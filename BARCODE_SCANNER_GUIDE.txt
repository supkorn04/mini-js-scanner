1. INTRODUCTION & GOAL
================================================================================
In warehouse management systems (WMS), inventory tracking, and retail apps,
reading barcodes directly from a smartphone browser (without requiring the user
to install a native app from the App Store / Play Store) is a game changer.

Our goal in this project was:
- Scan 1D barcodes (cartons, lot numbers, bottles, parts) AND 2D QR codes.
- Work seamlessly on Android Chrome, iOS Safari, and Desktop webcams.
- Scan any length of characters (not hardcoded to 7 digits).
- Provide instant feedback (vibration + UI match + diagnostic HUD).
- Run efficiently at ~10 FPS so phones do not overheat or lag.

================================================================================
2. THE CORE PROBLEM: WHY BARCODE SCANNING ON THE WEB IS TRICKY
================================================================================
When you hold a physical barcode in front of a phone camera:
1. A 1D barcode is NOT text: it is a sequence of black and white bars whose
   EXACT mathematical width ratios encode characters.
2. If an image is 10% blurry, a human can still read "2604005", but a computer
   vision algorithm cannot determine whether a stripe is 1 unit or 1.5 units wide.
3. High-resolution video streams (e.g. 1080p) require heavy CPU processing. If
   you try to decode 60 frames per second on a mobile browser using pure JavaScript,
   the phone's CPU throttles, frame rates drop to 2 FPS, and the phone gets hot.
4. Browser security requires HTTPS for camera access (`navigator.mediaDevices`).
   It will fail completely over plain HTTP (except on localhost).

================================================================================
3. THE ARCHITECTURE & TECHNOLOGIES USED
================================================================================

3.1 HTML5 MediaDevices (`navigator.mediaDevices.getUserMedia`)
--------------------------------------------------------------
This is the standard Web API that asks the operating system for access to video
input devices (cameras).
- `facingMode: { ideal: 'environment' }` tells the browser: "Prefer the back-facing
  camera if available."
- Note: We do NOT force strict hardware constraints (like forcing 4K resolution
  or manual focus modes) because many mobile camera drivers will crash or reject
  the stream with an `OverconstrainedError`.

3.2 Strategy A: Native `BarcodeDetector` API (Hardware Accelerated)
-------------------------------------------------------------------
- What is it? Modern Android Chrome and Chromium browsers have a built-in
  C++/GPU-accelerated barcode engine powered by Google Play Services MLKit.
- Why it is great:
  * Runs directly against the `<video>` element.
  * Super fast (sub-20ms per frame).
  * Extremely tolerant to curved bottles, skewed angles, and screen glares.
- Limitation:
  * It is NOT supported in every browser (e.g., iOS Safari and older desktops
    do not have `window.BarcodeDetector`).

3.3 Strategy B: ZXing ("Zebra Crossing") via JS (Software Fallback)
-------------------------------------------------------------------
- What is it? The industry-standard open-source barcode processing engine.
- We used version: `@zxing/library@0.21.0` (UMD bundle).
  * CAUTION: Newer versions like `0.23.0` have breaking changes and known
    regressions when decoding 1D Code 128 barcodes from video streams!
- Key components of ZXing:
  1. `MultiFormatReader`: The decoding engine that accepts configuration hints.
  2. `HTMLCanvasElementLuminanceSource`: Converts RGBA canvas pixel data into
     grayscale luminance values.
  3. `HybridBinarizer`: A crucial algorithm! It divides the image into blocks
     and computes adaptive black/white thresholds. This solves uneven lighting
     (shadows, highlights on glossy labels).
  4. `BinaryBitmap`: The 1-bit black/white matrix fed directly into the decoder.

3.4 HTML5 `<canvas>` as a Frame Buffer
--------------------------------------
Instead of letting a library guess how to render the video, we manually create an
offscreen `<canvas>` with `willReadFrequently: true`:
- Video frame -> Canvas `drawImage()` -> Raw Pixel Data -> ZXing Engine.
- By matching `canvas.width = video.videoWidth`, we guarantee 1:1 pixel sharpness
  without any CSS distortion or downscaling.

4. STEP-BY-STEP CODE BREAKDOWN (FROM APP.JS)
================================================================================

4.1 Step 1: Centralized Configuration
--------------------------------------
Never scatter configuration numbers all over your script. Put them at the top:

```javascript
const SCANNER_CONFIG = {
    scanIntervalMs: 100,      // ~10 FPS: smooth enough to feel instant, light on battery
    vibrateDurationMs: 100,   // Haptic vibration feedback
    zxingFormats: [           // Formats we want to actively decode
        ZXing.BarcodeFormat.CODE_128,  // Warehouse barcodes
        ZXing.BarcodeFormat.QR_CODE,   // QR codes
        ZXing.BarcodeFormat.EAN_13,    // Retail consumer goods / bottles
        ZXing.BarcodeFormat.EAN_8,
        ZXing.BarcodeFormat.UPC_A,     // Retail products
        ZXing.BarcodeFormat.UPC_E,
        ZXing.BarcodeFormat.CODE_39,
        ZXing.BarcodeFormat.ITF
    ]
};
```

4.2 Step 2: Camera Access & Defensive Fallback
----------------------------------------------
Do not assume every phone will accept rear camera constraints. Use a 2-step loop:

```javascript
async function openCamera() {
    const attempts = [
        // Attempt 1: Target primary rear-facing camera
        { video: { facingMode: { ideal: 'environment' } }, audio: false },
        // Attempt 2: Fallback to any camera available (e.g. laptop webcam)
        { video: true, audio: false }
    ];

    let lastErr;
    for (const constraint of attempts) {
        try {
            return await navigator.mediaDevices.getUserMedia(constraint);
        } catch (e) {
            lastErr = e; // Try next fallback
        }
    }
    throw lastErr; // All attempts failed
}
```

4.3 Step 3: Dual-Engine Architecture
-------------------------------------
Check if native hardware scanning is supported. If yes, use it; otherwise, fall
back to ZXing software decoding:

```javascript
if ('BarcodeDetector' in window) {
    // === NATIVE HARDWARE ACCELERATION (Android / Chrome) ===
    const detector = new BarcodeDetector();
    const tick = async () => {
        if (!running) return;
        try {
            const barcodes = await detector.detect(video);
            if (barcodes.length > 0) {
                onScanSuccess(barcodes[0].rawValue, barcodes[0].format, 'Native BarcodeDetector');
                return;
            }
        } catch (e) {}
        timerId = setTimeout(tick, SCANNER_CONFIG.scanIntervalMs);
    };
    tick();
} else {
    // === SOFTWARE HYBRID BINARIZER (iOS Safari / Desktop) ===
    const reader = new ZXing.MultiFormatReader();
    // Hints setup...
    const canvas = document.createElement('canvas');
    const ctx = canvas.getContext('2d', { willReadFrequently: true });

    const tick = () => {
        if (!running) return;
        if (video.videoWidth > 0) {
            canvas.width = video.videoWidth;
            canvas.height = video.videoHeight;
            ctx.drawImage(video, 0, 0, canvas.width, canvas.height);

            try {
                const luminance = new ZXing.HTMLCanvasElementLuminanceSource(canvas);
                const bitmap = new ZXing.BinaryBitmap(new ZXing.HybridBinarizer(luminance));
                const res = reader.decode(bitmap);
                if (res) {
                    onScanSuccess(res.getText(), res.getBarcodeFormat(), 'ZXing HybridBinarizer');
                    return;
                }
            } catch (e) {
                // NotFoundException happens every frame where no barcode is in view
            }
        }
        timerId = setTimeout(tick, SCANNER_CONFIG.scanIntervalMs);
    };
    tick();
}
```

4.4 Step 4: Real-time Telemetry (Diagnostic HUD)
------------------------------------------------
A good developer never guesses what the camera is seeing.
The HUD measures:
1. Actual video feed dimensions (`video.videoWidth` x `video.videoHeight`).
2. Actual processing FPS (frames processed per second).
3. The name of the physical camera lens (`track.label`).
4. Which engine is currently active (Native vs. ZXing).

4.5 Step 5: Clean Teardown & Power Savings
------------------------------------------
When scanning stops, or when the user switches browser tabs, ALWAYS release the
hardware:
```javascript
function stopScanner() {
    running = false;
    clearTimeout(timerId);
    if (stream) {
        stream.getTracks().forEach(track => track.stop()); // Shuts off camera LED & sensor
        stream = null;
    }
    video.srcObject = null;
}

// Auto-stop when switching tabs or locking screen:
document.addEventListener('visibilitychange', () => {
    if (running && document.hidden) stopScanner();
});
```

5. THE CRITICAL DIFFERENCE: WAREHOUSE LABELS VS. BOTTLES & SCREENS
================================================================================

Why did your company barcode scan easily, while the bottle and computer screen failed?

1. Symbology (Type of Code):
   - Warehouse labels: Almost always **Code 128** (variable-length alphanumeric).
   - Retail bottles & cans: **EAN-13** (13 digits) or **UPC-A** (12 digits).
   - If your configuration only listed `[CODE_128]`, the engine completely ignores
     bottles!

2. Cylinder Curvature:
   - When a barcode wraps around a round bottle, the vertical bars curve away from
     the camera.
   - The spaces between bars appear compressed toward the edges.
   - ZXing's standard linear 1D reader measures exact bar spacing across a straight
     line; when bars are curved, the checksum fails.
   - *Fix:* Native `BarcodeDetector` handles this with neural-network pattern
     matching, or hold the bottle so the barcode faces the camera as flat as possible.

3. Reflections & Gloss:
   - Plastic bottles have a white specular reflection (glare) right down the middle.
   - That white streak wipes out 2 or 3 black bars, destroying the signal.
   - *Fix:* Tilt the bottle 15 degrees to deflect the glare away from the lens.

4. Computer Screen Moiré:
   - Scanning a barcode displayed on a PC monitor produces digital interference
     patterns (Moiré effect) because the camera pixel grid clashes with the monitor's
     subpixel grid.
   - Low resolution (e.g. 360p) will blur these stripes into a grey blob.

5. Macro Focus:
   - Phone cameras cannot focus closer than ~10-15 cm unless they switch to a macro lens.
   - If you hold a bottle too close to fill the screen, it becomes a blurry blur.
   - Keep the bottle 20-30 cm away where the lens is razor-sharp.

6. KEY MISTAKES TO AVOID (WHAT WE LEARNED THE HARD WAY)
================================================================================

[MISTAKE 1] Using `object-fit: cover` on `<video>` without realizing it crops:
  - If your CSS has `object-fit: cover`, the screen crops the camera feed to fill
    the container.
  - The user points their target box at the barcode, but on the actual camera frame,
    the barcode is near the edge or partially out of view!

[MISTAKE 2] Hardcoding digit validation rules:
  - In the reference project, `LOT_PATTERN = /^\d{7}$/` silently dropped any code
    that wasn't exactly 7 digits.
  - Retail barcodes (12 or 13 digits) were decoded but thrown away immediately.

[MISTAKE 3] Trusting `@latest` CDN versions blindly:
  - `@zxing/library@latest` pulled version `0.23.0`, which had subtle regressions
    in video stream initialization.
  - Always pin your library versions (e.g. `@0.21.0`) in production.

[MISTAKE 4] Running decode loops at 60 FPS:
  - Decoding is mathematically expensive.
  - Polling at 100ms (~10 FPS) gives 99.9% of the user responsiveness while saving
    80% of CPU and battery life.
